# BazaarSaathi

**Decision support for the street vendor who can't afford to guess wrong.**

🔗 **Live app:** https://bazzar-sathi.vercel.app

## The problem

A street vendor decides how much to prepare every single day with no data, no
forecasting, and no room for error on tight working capital. Overstock and the
excess spoils or gets thrown out — that's cash the vendor can't get back.
Understock and they turn away paying customers on their best days. Today this
decision is pure gut feel.

## The approach

1. **Forecast** — a Random Forest Regressor trained on the vendor's sales
   history predicts tomorrow's demand from weather, weekday/weekend, and
   local-event signals.
2. **Simulate (BazaarTwin)** — rather than trusting one point forecast, the
   engine samples 500 plausible variations of tomorrow's conditions and
   forecast noise, producing a full distribution of possible demand outcomes.
3. **Survival Stock** — for every candidate stock level (60–130 units), the
   engine computes expected profit, expected waste cost, and stockout
   probability across all 500 simulated futures, then recommends the level
   that best matches the vendor's chosen risk personality:
   - **Protect Cash** — minimize wasted stock/spend, even if it means running
     out some days.
   - **Balanced** — maximize expected profit.
   - **Maximize Sales** — minimize the chance of running out, even if it means
     some waste.
4. **Why-explainer** — a plain-language breakdown of how much rain, weekend,
   local events, and the recent sales trend each shift the forecast.
5. **Savings calculator** — compares naive stocking (rounding the raw ML
   forecast) against the recommended Survival Stock, showing the rupees of
   waste avoided and a projected monthly savings figure.

## Features

**Core decision engine**
- ML demand forecast (Random Forest, trained on true demand rather than
  stockout-censored sales — see [Data disclosure](#-data-disclosure))
- 500-future Monte Carlo simulation (BazaarTwin)
- Survival Stock recommendation with 3 risk personalities
- Why-explainer, savings calculator, stock-level comparison table
- 14-day sales trend chart and model accuracy (MAE/RMSE/R²) on the Dashboard
- Live weather pre-fill (tomorrow's real Mumbai forecast via Open-Meteo)

**Bazaar Network**
- **Bazaar Mesh** — matches your surplus/shortage against a small set of
  nearby vendors selling the same item
- **Bazaar Intelligence** — pooled, anonymized demand patterns from nearby
  vendors, for a stall without enough sales history of its own yet
- **Bazaar Chat** — a real, persisted, live chat room for nearby vendors
  (Supabase Auth + Postgres + Realtime)

**Accessibility**
- Full English / Hindi / Marathi translation, including voice recognition
  language
- Voice input for logging sales ("Sold 91, 9 left") via the Web Speech API
- Client-side OCR for scanning a wholesale bill (tesseract.js)

Voice input and OCR are demo-scoped: they parse and display structured data
but don't write to a backend inventory table (there isn't one) — see
[What's implemented vs. future scope](#whats-implemented-vs-future-scope).

## ⚠️ Data disclosure

**All vendor/sales data in this prototype is synthetic**, generated by
[`backend/app/data/generate_data.py`](backend/app/data/generate_data.py) with
realistic-but-fabricated patterns (rain suppresses demand, weekends/events
boost it, mild upward trend, random noise). Bazaar Mesh and Bazaar
Intelligence's "nearby vendors" are also synthetic. No real vendor, sales, or
transaction data is used anywhere in this project. This is a hackathon
prototype meant to demonstrate the approach, not a validated production
forecasting system.

## Tech stack

- **Backend:** FastAPI (Python), scikit-learn (RandomForestRegressor),
  pandas/numpy. No database on the backend itself — CSV + in-memory only.
- **Frontend:** React + Tailwind CSS (Vite).
- **Auth / chat / profiles:** Supabase (Postgres, Auth, Realtime) — optional;
  the rest of the app works with or without it configured.

## Setup & run

### Backend

Requires **Python 3.11+** — `requirements.txt` is frozen to exact versions
(pandas 3.x / numpy 2.5 / scikit-learn 1.9) that only ship wheels for recent
Python. On an older interpreter, relax the pins (`pip install fastapi
uvicorn[standard] pandas numpy scikit-learn joblib pydantic` unpinned) instead.

```bash
cd backend
python -m venv venv
source venv/Scripts/activate      # Windows Git Bash; use venv/bin/activate on macOS/Linux
pip install -r requirements.txt

# (optional — vendor_sales.csv and model.pkl are already committed)
python -m app.data.generate_data
python -m app.data.generate_neighborhood_data
python -m app.models.forecast_model

uvicorn app.main:app --reload --port 8000
```

API docs (Swagger UI) available at `http://127.0.0.1:8000/docs`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. The frontend expects the backend at
`http://127.0.0.1:8000` by default (override with `VITE_API_BASE`, see
`.env.example`).

### Optional: vendor login + Bazaar Chat (Supabase)

1. Create a free project at [supabase.com](https://supabase.com).
2. In the SQL Editor, run [`backend/supabase_schema.sql`](backend/supabase_schema.sql)
   once — creates the `profiles` and `messages` tables with row-level
   security, and enables Realtime on `messages`.
3. In **Authentication → Providers → Email**, turn off "Confirm email" for a
   frictionless demo (sign-up returns a session immediately instead of
   requiring an email link).
4. Copy `frontend/.env.example` to `frontend/.env.local` and fill in
   `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` from your project's
   Settings → API page.

Without this, the app runs exactly the same — the login button and Bazaar
Chat section simply don't render.

## API endpoints

| Method | Path                      | Description                                                                       |
|--------|---------------------------|-------------------------------------------------------------------------------------|
| GET    | `/dashboard`              | Today's vendor stats (prepared, sold, unsold, revenue, waste, profit)               |
| GET    | `/forecast`               | Raw ML demand prediction for tomorrow given weather/event params                    |
| POST   | `/simulate`               | Full BazaarTwin engine: Survival Stock + distribution + why + savings               |
| POST   | `/mesh/match`             | Bazaar Mesh: matches today's surplus/shortage against nearby vendors                |
| GET    | `/model-info`             | Forecaster quality metrics (MAE/RMSE/R², top feature importances)                   |
| GET    | `/neighborhood-insights`  | Bazaar Intelligence: pooled rain/weekend/event demand impact % across nearby vendors |
| GET    | `/sales-history`          | Last N days of actual sales/profit, for the Dashboard trend chart                   |

All routes are also available under an `/api` prefix (e.g. `/api/dashboard`)
for the unified Vercel deployment.

## What's implemented vs. future scope

**Implemented:** synthetic-data-trained demand forecasting, 500-future Monte
Carlo simulation, Survival Stock with 3 risk personalities, why-explainer,
savings calculator, stock comparison, sales trend chart, live weather
pre-fill, Bazaar Mesh, Bazaar Intelligence, Bazaar Chat with real vendor
login (Supabase), voice-input and OCR demos, and full English/Hindi/Marathi
support.

**Explicitly future scope:**
- Production-grade OCR that writes straight into inventory, not just a preview.
- Bazaar Intelligence on live vendor data instead of synthetic neighbors.
- PM SVANidhi scheme discovery and eligibility guidance.
- UPI/POS integration so sales history builds itself automatically.
- Real vendor sales data replacing the synthetic training set.
- More cities, more languages, and real hyperlocal event data.
- Offline-friendly PWA support for patchy mobile networks.

## Deployment

Single Vercel project, both services. The root [`vercel.json`](vercel.json)
declares the frontend (Vite) and backend (FastAPI) as one multi-service
project, with `/api/*` routed to the backend and everything else to the
frontend:

```json
{
  "services": {
    "frontend": { "root": "frontend", "framework": "vite" },
    "backend": { "root": "backend", "framework": "fastapi", "entrypoint": "app/main.py" }
  },
  "rewrites": [
    { "source": "/api(/.*)?", "destination": { "type": "service", "service": "backend" } },
    { "source": "/(.*)", "destination": { "type": "service", "service": "frontend" } }
  ]
}
```

To deploy your own copy: push to GitHub, import the repo in Vercel (it
auto-detects both services), add `VITE_SUPABASE_URL` /
`VITE_SUPABASE_ANON_KEY` as environment variables if you want login/chat
live, and deploy. CORS is a non-issue since frontend and backend share an
origin.
